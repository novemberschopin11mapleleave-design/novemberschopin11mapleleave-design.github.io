01 / Workflow

把模糊任务
拆成可执行步骤

先问清楚输入、上下文、输出契约和人工确认点，再决定模型该在哪一步做什么。这样团队能更早发现错误假设，而不是等 Agent 跑偏后返工。

证据：SKILL.md 的核心规则与 quality checks；下一步接结构化输出与失败样例评测。

Project 01 / DSE Writing Lab / Prototype

先把学习流程，
做成可以用的界面。

这是 AI 英语写作学习产品的规则批改前端。下方嵌入的批改页可以直接编辑作文、切换文体与批改强度，并即时生成改写、批注和替换词；当前使用示例文本与本地规则，没有调用 LLM，也不是 Agent 系统。

The problem

写作学习的反馈往往散落在「原文、改写、批注、替换词、复习」几个环节里。通用语法工具不按 DSE 写作场景组织，学生看到了改动，却不知道下一步该练什么。

The approach

把流程拆成原文与改写对照、错误说明、替换表达、个人词库和打字练习；做多栏界面与文体 / 强度选项。页面与交互由 AI Coding Agent 辅助实现和迭代，再在真实浏览器里逐项验证。

The result

规则批改页可交互：编辑原文、切换文体 / 强度、查看语法修正与词汇升级、复制改写版；词库与练习流程在本地存储中完成。当前是示例文本，没有真实模型调用，也没有独立线上部署。

Next

如果要继续，会先接服务端 API 与 LLM，约束结构化输出，再做基础评测、账户与云端部署；在这些完成之前，不把它写成「已接入 LLM」。

Project 02 / DSE Writing Polish / Skill Spec

把改写规则，
写成 Agent 能加载的 Skill。

这是一个平台无关的写作改写 Skill：定义输入、行为边界、文体适配、词汇解释与输出格式。它是可复用的指令与工作流，不是已部署的自主 Agent 服务，也不提供作文评分。

The problem

通用改写容易改掉原意、立场或学生自己的声音；只给同义词列表，也无法告诉学生某个词在具体句子里是否自然。模型需要明确的行为边界。

The approach

把 Skill 拆成必需输入、保留原意、文体与语气适配、语境化词汇建议、默认输出格式和质量检查。明确禁止虚构数据、引用或更强的结论。

The result

公开的 GitHub 仓库，包含 README、SKILL.md、风格参考与改写示例；可被 Claude Code、Codex 或其他兼容 harness 加载。当前没有运行时服务，也没有评分能力。

Next

把它接进真实应用：调用 LLM API、约束结构化输出、记录失败样例并做基础评测；如果要做 Agent，再补工具调用与人工确认节点。
